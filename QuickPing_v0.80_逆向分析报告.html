2分析方法与工具链

按用户要求，使用仓库 https://github.com/morluto/rea（REA，实际安装为 rea-agents v6.5.0）作为分析编排层，Rizin v0.9.1 作为底层反汇编/分析引擎，对目标进行静态逆向。

分析步骤

  1. 类型判定：确认目标为原生 32 位 PE（非 .NET、非加壳），选定 Rizin 作为后端。
  2. 环境搭建：安装 Rizin，编写 REA 封装脚本 run-rea.ps1，以"命令 → 转储文件"方式批量驱动 Rizin。
  3. 全量分析：执行 aaa 完整分析并枚举全部函数。
  4. 元数据提取：导入表（ii）、字符串（iz/izz）、节区、PE 资源与版本信息。
  5. Delphi 结构还原：解析嵌入的 DFM 窗体资源还原 UI；通过方法表与交叉引用定位全部事件处理函数。
  6. 核心逻辑反编译：逐段反汇编并人工还原 PingThread 构造/执行、结果回写、颜色映射、状态文本、注册表掩码等关键函数。
Delphi 专项处理：程序字符串为 GBK 编码，Rizin 的 ps 命令显示乱码，故采用 p8 十六进制转储后按代码页 936（GBK）解码；Delphi 长字符串头部为 ffffffff（引用计数）+ int32 长度，实际数据位于 +8 处；push <地址>; 清理; ret 是 Delphi try/finally 的延续块模式，函数实际范围需跨越这些块判定。

3PE 结构与 Delphi 特征

  • 32 位 PE，i386 架构，映像基址 0x400000，标准 Delphi 布局（代码段 + 只读数据段 + 资源段）。
  • 链接 Delphi RTL/VCL 运行库：大量 0x40xxxx–0x41xxxx 区间的系统例程，如 0x403a3c（LStrAsg，字符串赋值）、0x407e14（IntToStr）、0x40880c（Format）、0x4026f4/0x40270c（堆内存分配/释放）。
  • 窗体以 DFM 二进制资源内嵌，完整还原出主窗体 TForm1 及其全部控件（见第 5 节）。
  • 字符串资源集中在 0x45a6xx–0x45caxx 区间，全部为 GBK 编码的中文提示与英文网络术语混合。
  • 版本资源：OriginalFilename=QckPing.exe，版权信息指向作者陈斌斌。

6程序总体流程

程序启动
  └─ DPR 入口：以 "quickping" 做单实例互斥检查
  └─ FormCreate (0x45bfd8)
       ├─ 初始化 IP 前输入框默认值（255 / 255.255.255. / 0.0.0. 等）
       ├─ 初始化默认子网掩码 "255.0.0.0" (0x45c498)
       ├─ Win9x 注册表读取本机真实掩码（见第 11 节）
       └─ 界面初始化（表格列标题、待测黄色底色）

点击"开始" startbuttonClick (0x45b8bc)
  ├─ WSAStartup 初始化 Winsock（失败提示"初始化Winsock时发生错误" 0x45c46c）
  ├─ 由 IP 前缀 + 掩码计算目标网段主机列表（当前索引 0x378 → 终止索引 0x37c）
  ├─ grid2 全部置为待测色（黄 0xFFFF）
  └─ 按线程数（≤40）循环创建 PingThread：
       每线程领取一批主机序号，构造参数传入目标 IP、超时、TTL、
       grid1/grid2 引用、行号、mod16/div16 坐标、是否查 MAC 标志

PingThread.Execute（0x45a000–0x45a632，每个目标主机一轮）
  ├─ IcmpCreateFile 打开句柄
  ├─ inet_addr 转换目标 IP
  ├─ IcmpSendEcho 发送 56 字节探测包（带超时）
  ├─ 拷贝 28 字节 ICMP_ECHO_REPLY 到线程对象 +0x34..+0x4f
  ├─ 成功：[+0x68] = RTT（回复中的往返时间）
  │  失败：[+0x68] = GetLastError()（IP_STATUS 错误码）
  ├─ IcmpCloseHandle + WSACleanup
  └─ 结果回写（见第 8 节）→ 取下一台主机，直到批次结束
       └─ 线程结束：活动线程计数 -1（0x45bd54: dec [eax+0x34c]）

timer1Timer (0x45bd5c)
  ├─ 轮询活动线程计数（Form1+0x34c）
  ├─ 全部归零 → 扫描完成统计：
  │    统计行色为 0x8000（深绿）/ 0xFF00FF（品红）的行数 = 响应主机数
  └─ 刷新状态显示；若还有未扫区间且处于循环模式则继续下一轮

"保存" savetolog1Click (0x45c62c)
  └─ 将 grid1 明细按逗号分隔（"," @ 0x45c7e0）导出为 CSV（文件名含 quickping @ 0x45cabc）

"精简" dealresultbuttonClick (0x45c7e4)
  └─ 对结果表格做精简/整理显示

8结果回写与显示逻辑

回写段位于 Execute 续段 0x45a1ea–0x45a5dc，是全文逻辑最密集的部分。颜色函数 0x459e64 在整个程序中只有一个调用点（0x45a1ed）。完整还原如下：

color = ColorOf([+0x68])              ; 0x459e64: 值0 → 0x8000(深绿)；错误码/默认 → 0xFF(红)

if [+0x68] == 0:                      ; ★ 以"结果==0"判定在线（RTT=0ms 的成功）
    grid2[mod16, div16] = 0xFFFF00    ; 先置青色（过渡态）
    grid1 行底色 = 0xFFFF00
    第0列 = IP 字符串 [+0x50]

    if [+0x84] 标志置位:              ; 需要查 MAC
        GetIpNetTable(call 0x4597e0, 缓冲 0x12c4 字节, 最多 200 项)
        if 调用成功:
            遍历表项（步长 24 字节：+0x04 dwIndex, +0x0C..+0x13 bPhysAddr, +0x14 dwAddr）
            找到 dwAddr == [+0x54] 的表项:
                第1列 = MAC，格式 "%2.2x:%2.2x:%2.2x:%2.2x:%2.2x:%2.2x" (0x45a664)
            遍历完未找到: 第1列 = ''
        else:
            第1列 = "error:" + IntToStr(返回值)   ; "error:" @ 0x45a690
    else:
        第1列 = ''

    → 公共路径 (0x45a4c2):
    gethostbyaddr(&[+0x54], 4, AF_INET)   ; 经 0x446cf4 包装
    if 反查成功:
        grid2 = 0xFF00(绿); 行底色 = 0xFF00FF(品红)
        第2列 = 主机名; 第3列 = 状态文本("在线")
    else:
        grid2 = color; 行底色 = color     ; result=0 时为深绿 0x8000

else:                                  ; ★ RTT>0 或出错 → 按失败处理
    grid2[mod16, div16] = color(红)
    行底色 = color
    第0列 = IP; 第1列 = ''; 第2列 = ''
    第3列 = FormatStatus([+0x68])      ; 0x459960，见第 9 节
    → 清理（IcmpCloseHandle + WSACleanup）
注意：成功路径要求 [+0x68]==0，而成功时 [+0x68] 写入的是 RTT。这意味着该判定只在 RTT 恰为 0ms 时走"在线"分支——详见第 12 节"程序怪癖"。

状态文本函数 FormatStatus（0x459960–0x459c3a）

对 [+0x68] 做二叉比较树分派，各分支以 mov edx, <串地址>; call 0x403a3c（LStrAsg）赋值；未知代码走默认分支：IntToStr(值) 拼接到 "ICMP error #"（0x459e54）之后。

10颜色语义

程序使用 Delphi TColor（0x00BBGGRR）表达主机状态。颜色函数 0x459e64 已逐字节验证：值==0 分支（0x459f67）为 mov eax, 0x8000; ret，默认分支（0x459ff7）为 mov eax, 0xFF; ret。

颜色TColor 值含义
黄色0xFFFF待测（初始状态，grid2 全图底色）
青色0xFFFF00过渡态：结果==0 的主机刚进入成功分支
绿色0xFF00grid2 成功且反查到主机名（最终态）
品红0xFF00FFgrid1 行成功且反查到主机名（最终态）
深绿0x8000成功但未反查到主机名（颜色函数对值 0 的返回）
红色0xFF失败（一切已知错误码与默认分支均返回红）

Timer1 完成统计时，以行色为 0x8000 或 0xFF00FF 的行数作为"响应主机数"。

11Win9x 注册表子网掩码获取

FormCreate（0x45bfd8）内的一段逻辑（引用 0x45c498、0x45c4ac、0x45c4bc）还原如下——这是典型的 Windows 95/98 获取本机 IP 配置的手法（Win9x 没有 GetAdaptersInfo）：

掩码 = "255.0.0.0"                          ; 默认值 (0x45c498)
for i in 0..10:                             ; 循环 11 次
    子键 = "System\CurrentControlSet\Services\Class\NetTrans\"
           + Format("%4.4x", i)             ; 0x45c4ac，如 \0000、\0001...
    打开子键，读取 "IPAddress" (0x45c4f8)
    if 与本机 IP 匹配:
        掩码 = 读取 "IPMask" (0x45c50c)
        break

NetTrans 键下每个子项对应一个绑定的网络协议实例，%4.4x 模板循环 11 次（0–10）足以覆盖常见网卡数量。整个注册表访问为只读。

12程序怪癖与疑似 Bug

RTT>0 的成功主机会被显示为失败。
Execute 成功时把 RTT 写入 [+0x68]（0x45a19a 处 [+0x68]=[+0x38]），但回写逻辑（0x45a1f8：cmp dword [eax+0x68], 0）以 [+0x68]==0 作为"在线"判据。因此：
  • RTT = 0ms（Win9x 时代局域网中极常见，计时精度低）→ 走成功分支，显示青/绿/品红/深绿 + "在线"。
  • RTT > 0ms 的成功响应 → 落入失败分支，grid2 变红，返回信息列显示 ICMP error #<RTT值>（因为 RTT 数值不在状态码表中，走默认拼接分支）。

也就是说：一台响应时间为 3ms 的主机会被显示为红色"ICMP error #3"。推测作者原始意图是"以状态码 0（IP_SUCCESS）判定在线"，但成功路径写入的却是 RTT 而非状态码，两者混淆导致该行为。在当年的局域网环境下（大量 0ms 响应）软件"看起来工作正常"，该缺陷得以保留。

其他观察：

  • 工作线程直接操作 VCL 控件（Execute 内直接写 grid1/grid2 单元格），未用 Synchronize——Delphi 中属不安全写法，多线程并发刷新网格时可能产生竞态或界面闪烁，但在当年低并发（≤40 线程、慢速机器）场景下大体能用。
  • GetIpNetTable 缓冲按最多 200 条表项（0x12c4 字节）固定分配；ARP 表超过 200 项的极端环境会截断。
  • MAC 格式化串 "%2.2x:%2.2x:..." 使用冒号分隔（而非 Windows 常见的连字符风格）。

13安全与行为评估

结论：无恶意行为，属于正常的网管工具。
评估项结论
网络行为仅向用户指定网段发送标准 ICMP 回显请求；无 TCP/UDP 连接、无下载、无回传
注册表只读（NetTrans 键读取掩码），无写入、无自启动项
文件系统仅在用户操作"保存"时导出 CSV 日志，无其他文件写操作
进程/权限无进程注入、无提权、无服务安装；仅创建自身工作线程
代码混淆无壳、无混淆，标准 Delphi 编译产物
隐患（非恶意）工作线程直接操作 VCL 控件（竞态风险）；固定大小缓冲（200 条 ARP 表项、256 台上限）；RTT 判定缺陷（第 12 节）
