## QuickPing2 复刻版开发（quickping2/）

- 目标：复刻 QuickPing v0.80 并优化 IP 在线检测准确性。用户明确授权动手实现。
- 技术栈：Python 3.13（纯标准库）+ 单页 HTML 前端 + 本地 HTTP 服务（127.0.0.1:8730）。
- 探测引擎与原程序同源 API：ctypes 调 IcmpCreateFile/IcmpSendEcho（免管理员），payload 复刻 "PING, written by CBB!"。
- **准确性优化（针对原版不准的根因）**：
  1. 三阶段探测：ICMP(200ms) → ICMP 加倍超时重试（挽回 ARP 未命中丢首包）→ SendARP 兜底（挽回防火墙禁 ping 的误判离线）
  2. 在线设备顺带 SendARP 解析 MAC（替代原版被动查 GetIpNetTable）
  3. UI 用颜色区分 method（绿=ICMP 在线 / 蓝=ARP 兜底在线），统计含在线率与 by_method
- UI 复刻：IP 段参数栏（132.105.112.0-255/超时200/线程20）+ 16×16 矩阵 + 列表视图 + 起始/终止/用时/响应数统计 + 开始/停止/表格模式/精简结果/保存/关闭，CSV 默认名 pinglog.csv。
- 调试记录（重要教训）：
  - ctypes 64 位进程必须显式声明 IcmpCreateFile.restype=HANDLE，否则句柄截断 → access violation
  - SendARP pMacAddr 用 (c_ulong*2)() 数组而非 string_buffer（argtype 不匹配）
  - **ThreadPoolExecutor 工作线程内调 shutdown(wait=True) 会自己 join 自己 → RuntimeError → running 永不翻转**；改用完成计数器 _bump_done()，绝不在 worker 内同步 shutdown
  - 环回地址 SendARP 会阻塞数秒 → _arp_useful() 跳过 127.*
- 验证：10 主机 0.01s 扫完，127.0.0.0 正确判离线；HTTP API 全通（/、/api/start、/api/status、/api/export）。
- 文件：quickping2/server.py（后端引擎+API）、quickping2/index.html（前端）、quickping2/test_smoke.py（冒烟测试）。
- 运行方式：`python server.py` → 自动打开 http://127.0.0.1:8730/。

## 「无法运行」修复（同日 15:11）

- 根因 1：助手后台常驻实例占用 127.0.0.1:8730，用户手动启动 server.py 时 WinError 10048 崩溃。
- 根因 2（更隐蔽）：**Windows 下 ThreadingHTTPServer 的 allow_reuse_address=1 (SO_REUSEADDR) 允许两个进程静默绑定同一端口**，端口冲突检测完全失效——必须显式 allow_reuse_address=False 才能让 bind 抛 OSError。已建 QPHTTPServer 类修复。
- 修复：端口占用自动顺延 8730→8739（打印中文提示）+ start.bat 双击启动器（py -3 优先、python 兜底、ASCII 内容避免 GBK 乱码）+ 启动失败给中文错误与指引。
- 测试注意：公司机器有系统代理，urllib 访问 127.0.0.1 会走代理返回 502——本地自测要用 curl --noproxy '*'。
- 双实例场景已验证：主实例 8730 正常、第二实例自动落 8731 并提示。
