# 2026-10-26

## QuickPing2 新增检测协议 + 协议标签功能

- 需求：按此前方案增加新检测功能，且扫描结果要用**协议标签**显示每个 IP 支持哪些协议。
- `server.py` 探测引擎从三阶段扩为**四阶段**：
  1. ICMP → 2. ICMP 重试 → 3. ARP 兜底 → 4. **TCP 探测兜底**（445/80/443 依次 connect，open 或 refused(RST) 均判在线，nmap 同款 RST 语义）
- 新增函数：
  - `tcp_probe(ip, port, timeout_s)`：返回 open/refused/filtered；ConnectionRefusedError + winerror 10061/errno 111 → refused，其余 OSError → filtered
  - `nbns_query(ip)`：手写 NBNS 节点状态查询（UDP 137，通配名 `*` level-1 编码 "CK"+"AA"×15，qtype 0x0021），解析应答取工作站名（后缀 0x00 独立名优先）+ MAC；PTR 失败时的设备名兜底
- **协议标签**：每 IP 结果新增 `protos` 数组（ICMP/ARP/DNS/NBNS/SSH/HTTP/HTTPS/SMB/RDP），由 `_finish_online` 在 deep=True 时对在线设备探测 TCP_PROBE_PORTS(22/80/443/445/3389) + NBNS 生成
- 参数链路：`/api/start` 增加 `deep` 字段 → `Scanner.start(..., deep)` → `_work` → `probe_host`；前端新增「协议识别」复选框（默认开）
- CSV 增加 protocols 列（9 列）；表格视图新增「协议」列（彩色标签，服务类绿色、协议类蓝色）；矩阵新增橙色 `online-tcp` 类与图例；tooltip/详情栏显示协议
- 验证：127.0.0.1 → protos=[ICMP,DNS,HTTP,SMB,RDP]；网关 192.168.1.1 → [ICMP,ARP,DNS,HTTP,HTTPS]；真实扫 192.168.1.1-30 全链路 OK
- 踩坑记录：
  - 本机 loopback 关闭端口返回 Timeout/10013 而非 refused——Docker vpnkit 劫持 127.0.0.1 所致，真实 LAN 主机 RST 正常
  - 首次 DNS PTR 查询可能慢（冷缓存 ~15s），之后毫秒级
- 三个 exe 已重打包（console/portable/GUI，用 venv `envs/default` 的 PyInstaller，spec 在 build*/ 目录，路径均为绝对路径）
