## 端口扫描「IP 跳变」问题（用户反馈：输入 .3 实际扫 .38）

- 现象：输入框填 192.168.253.3，结果行显示实际扫描 192.168.253.38（后端 meta.ip 收到的是 .38）
- 排查：grep 确认当前 index.html 中 psIp 无任何赋值点（仅读取），排除代码自动填入
- 根因判定：**浏览器/WebView2 输入框历史自动补全**——用户此前输入过 .38，内联补全被回车/点按钮提交
- 修复：psIp/psPorts 加 autocomplete="off" autocorrect="off" spellcheck="false"，字段 name 改为随机名 qp_port_ip（避免浏览器按 id/name 记历史）；renderPorts 增加「扫描目标 IP ≠ 输入框当前值」红色告警
- 备注：那次扫的 .38 是真邮件服务器（25 SMTP / 110 POP3 / 143 IMAP 开放），扫描功能本身正常，只是目标错
- 状态：三个 exe 已全部重打包完成（10:19-10:39，GUI 版待用户关闭后于 10:39 补齐）

## 端口扫描改造（应用户反馈）

- ① **IP 不再自动填入**——showDetail 不再写 psIp，纯手动输入
- ② **默认扫全部端口**——UI 范围框默认「全部」(1-65535)，后端 /api/portscan 默认 ports 也改为「全部」；全端口扫描前端发 workers=256、timeout=0.8s
- ③ **TCP/UDP 协议区分**：
  - 新增 `udp_probe`：发探针数据报（53=DNS version.bind 查询、123=NTP client 包，其余 2 字节占位）；
    收到应用层应答=open；收到 ICMP 端口不可达（Windows 已 connect UDP socket 表现为 WSAECONNRESET/10054）=closed；
    无响应=unknown（开放与被过滤不可区分，UDP 固有三态）
  - UI 新增协议下拉：TCP / UDP / TCP+UDP；结果按协议分组统计
    （TCP: 开放/关闭/过滤；UDP: 开放/关闭/未知），开放端口标签带 TCP/UDP 前缀且 UDP 用蓝色
  - PortScanner results 增加 proto 字段；CSV 导出增加 proto 列（大写 TCP/UDP）
- 验证：127.0.0.1:9999 UDP → closed ✓；网关:123 UDP → closed ✓；TCP+UDP 混扫 summary 分组正确
  （tcp open=445 SMB,3389 RDP / udp closed+unknown）；HTTP 接口与 CSV 均正常；三个 exe 已重打包（09:58）
- 已知局限（诚实边界）：UDP 无响应时无法区分「开放但静默」与「防火墙过滤」，显示为「未知」；
  部分系统对 ICMP 不可达限速，UDP 关闭判定可能漏（nmap 同样限制）
