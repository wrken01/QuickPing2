  - **LLMNR(5355) 明确不做主动探测**：需要查询一个具体名字且只有认为自己是该名字的主机才应答，主动探测命中率极低，被动监听才有意义
  - API：POST `/api/discover`、`/api/discoverstop`；GET `/api/discoverstatus`、`/api/discoverexport`（CSV 表头 `ip,protocols,name,details,first_seen`）

## ④ 安防监控设备发现（已实施，Kane 要求「加上大华/海康/宇视的组播发现」）

- **关键结论：宇视没有公开的私有组播发现协议**。官方 EZTools 文档写明「按 IP 段搜索遵循 ONVIF」，实测宇视摄像机应答标准 WS-Discovery，Scopes 里含 name/hardware/version/serial/macaddr。因此不编造假报文，改为深挖 ONVIF Scopes —— 三家通用
- 协议依据（均有源码/抓包/官方文档，未猜测字段）：
  - 大华 DHIP：UDP 37810 / 组播 `239.255.255.251`，`method=DHDiscover.search`；32B 头 `20 00 00 00 "DHIP"` + 8×00 + len(LE32) + 00×4 + len(LE32) + 00×4，后接 JSON。依据 DahuaConsole `net.py dh_discover()`，与 CSDN 抓包字节一致。应答为 32B 头 + `client.notifyDevInfo` JSON（DeviceType/DeviceClass/SerialNo/Version/Vendor/IPv4Address/HttpPort/Port/VideoInputChannels）
  - 海康 SADP：UDP 37020 / 组播 `239.255.255.250`，XML `<Probe><Uuid/><MAC>ff-ff-ff-ff-ff-ff</MAC><Types>inquiry</Types></Probe>`。依据专利 CN111031286A + hiktools + 抓包。应答字段 DeviceDescription/DeviceSN/CommandPort/HttpPort/MAC/IPv4Address/SoftwareVersion/DSPVersion/BootTime
  - 大华 DVRIP（老设备）：UDP 5050 受限广播，32B `a3010001 ... 02000000`；应答 32B 头 + 二进制区，偏移据 DahuaConsole（hostname@8、Web@62、HTTPS@64、TCP@66、描述@88）
- `server.py` 新增：`DISCOVERY_FIXED_PORTS`（37810/37020/5050/3702）、`guess_camera_vendor()`（仅按明确品牌串/型号前缀推断，命中不了留空）、三组 build_query + 三个解析器、`parse_onvif_scopes()`（含 Types 判 IPC/NVR/解码设备）

- **踩坑：SADP XML 解析正则用 `(.*?)` 时，外层 `<Probe>` 会把整段内容吞成一个标签，内层字段全丢 → 值必须限定为 `([^<]*)`，只匹配叶子节点**
